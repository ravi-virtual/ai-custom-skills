# Proposal Templates

Fill every bracket with real, true details, then delete the guidance lines. Do not send a template unchanged.

## Bug fix or small change

```
[Client's exact symptom in their words, plus what it usually indicates.]
[First thing you would check and how you would confirm it, in one or two sentences.]

[One similar fix with an outcome: "On a [similar stack] I traced [problem] to [cause] and shipped the fix with tests in [time]."]

Two quick questions: [version/stack question], and [do you have logs/steps to reproduce?].
[With access to X, I can give you a fixed price for the fix today / the fix is typically N hours at my rate of Y.]
Happy to look at it as soon as I can see [repo/staging].
```

## New build or MVP

```
[The business goal in their words] is the real target, so I'd start by [the riskiest/most valuable part], not the full feature list.

How I'd approach it:
1. [Short discovery: confirm must-haves, cut the rest for v1]
2. [Build the core flow end to end first]
3. [Ship to a staging link early so you can react]

Relevant: [project, outcome, link].

To scope accurately I need: [question 1], [question 2].
I'd suggest [milestone 1 for $X over N days], then re-plan with real feedback. Want me to send a one-page plan after a 15-minute call?
```

## Automation or integration

```
Moving [data/process] from [A] to [B] automatically would remove [the manual work they described], and the tricky part is usually [edge case: duplicates, rate limits, auth, failures].

Plan: [map the process and failure cases] -> [build with <tool>] -> [run alongside the manual process for a week, with alerts on failure].

I built [similar automation] that saves [N hours/week or error rate]: [link or description].

Questions: [volume per day?], [which systems/APIs and who owns the credentials?].
Price: [$X fixed for the integration, including error handling and a short handover doc].
```

## Data, scraping or reporting

```
You need [dataset/report] that stays correct as [source changes], so I'd build it to detect breakage rather than silently return bad data.

Approach: [sample the source and confirm legality/terms] -> [extract and validate against rules] -> [deliver as CSV/DB/dashboard on a schedule].

Past result: [dataset size, accuracy, frequency].

Before quoting: [which fields, how many records, how often, source terms of use?]
```

Check that the source's terms and applicable law permit the collection before agreeing.

## Ongoing or retainer work

```
For ongoing [area] work, what matters is [response time, predictability, knowledge of your codebase], so I suggest [N hours/month at $X with a defined response window] and a monthly summary of what shipped.

[Proof of long-term work: "I've maintained X for 18 months with 99.9% uptime."]
Questions: [typical workload], [who prioritises tasks?].
A 2-week trial would show if the fit is right for both of us.
```

## Follow-ups

Wait a few days after the first message; one polite follow-up is enough.

```
Hi [Name], following up on [project]. One thought since I wrote: [new specific idea or relevant link]. If the timing has changed, no problem; if you'd like, I can send the one-page plan.
```

## Replying to an invitation

The client chose you, so confirm fit quickly and move to specifics:

```
Thanks for the invitation. From [post/message] I understand [goal]. Before I quote I'd like to confirm [2 questions]. I can start [date]. [One-line proof]. Would a 15-minute call [day] work?
```
